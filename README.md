# Architecture-Reference

Reference repo for the pattern we want every new full-stack Rust + Dioxus
project to follow. Future template for `cargo generate`-style spin-ups.

## The pattern

A single domain entity lives in **one place**. The macros do the
expansion to every surface: SeaORM entity for the DB, vox RPC trait for
the wire, wasm-clean DTO for the wasm client, Dioxus UI in any app.

For each entity (here: `Example`) we get:

| Symbol           | Where it lives          | Generated by           |
|------------------|-------------------------|------------------------|
| `Example`        | `example-proto`         | hand-written struct    |
| `ExampleEntity`  | `example-db`            | `EntityToModels` macro |
| `ExampleRepo`    | `example-proto`         | `EntityToModels` macro |
| `ExampleStorage` | `example-db`            | `EntityToModels` macro |
| `ExampleService` | `example-proto`         | hand-written vox trait |
| `ExampleService` impl | `apps/server`      | hand-written           |
| `ExampleClient`  | wasm/desktop via vox    | `#[vox::service]` macro |

- **Repo** = auto-generated CRUD (`get`, `list`, `create`, `update`, `delete`).
  No business logic. Storage backend is generic over SeaORM today and can
  swap to anything implementing `CrudStorage`.
- **Service** = hand-written domain surface. Composes repos, validates
  inputs, enforces auth, emits domain events. This is where logic lives.
- **Proto** = wasm-clean. SeaORM derives are gated behind `feature = "server"`
  so the same crate compiles on both sides of the network.

## Layout

```
apps/
  web/       Dioxus web (wasm)
  desktop/   Dioxus desktop
  server/    axum + vox + sea-orm — implements ExampleService
  db/        sea-orm-migration binary (creates tables, runs migrations)

crates/
  example-proto/  Single source of truth: types + traits + auto-gen Repo
  example-db/     SeaORM entities + migration definitions (server-only)
  example-ui/     Shared Dioxus components used by web + desktop
```

The same `example-proto` crate is consumed by:

- `apps/web` (wasm, only the wasm-clean DTOs + vox client)
- `apps/desktop` (native, same client surface)
- `apps/server` (with the `server` feature, full SeaORM + dispatcher)
- `apps/db` (with the `server` feature, just the entities)
